How I Think

I don’t enjoy building software for the sake of software. I like noticing repetitive work.

• If I repeat something three times, I automate it.

• If I can’t explain a decision, I build a system that records it.

• If something annoys me long enough, it eventually becomes a product.

My projects are not just code — they are answers to frustrations. SlipKitchen started because I wanted to track why my betting predictions failed. Portfolio-Ops because I hated updating my site manually. DevBrief because I have over 70 unfinished side projects and needed a dashboard to keep them alive.

I design workflows, model data, choose architecture, and then build. That’s what early-stage startups need: someone who can define what to build as well as how to build it.

DevBrief

Flutter · local-first · Drift

Why: I have over 70 unfinished projects. Some are dead, some promising, some forgotten. DevBrief continuously scans my computer, indexes projects, tracks Git activity, and tells me what's happening.

• Automated discovery and indexing of local projects.

• Signature-based detection for frameworks & languages.

• Local metadata store (Drift) to track lifecycle and activity.

• Auto-generates portfolio artifacts from real data.

• Tech: Flutter, SQLite via Drift.
